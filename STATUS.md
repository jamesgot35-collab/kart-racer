## Caveats (honest)
- **Never played on a real phone/tablet.** All testing is headless Chrome with software GL (5-9 fps), so real frame rate, touch feel and thermals are unmeasured. The Performance tier and the low-end default are reasoned from draw-call/triangle counts, not measured fps. Handling, drift and camera constants were NOT retuned (no human playtest data); only assist, skid marks, speed lines were added. CPU fairness was not statistically established (my study was noisy and removed); the autopilot test kart is handicapped to 0.9x top speed.
- Audio was verified by capture + measurement, never by ears. Cup-2 music is variants of the five existing pieces, not new compositions.
- Visual checks were done by looking at screenshots only; there may be small visual glitches I did not catch. Cup-2 tracks reuse the cup-1 prop generators with new skins/themes/layouts/hazards, so they look related to cup 1 rather than fully new.
- Browser-to-browser WebRTC is NOT verified: headless Chrome here cannot gather ICE candidates (tests/ice_probe.mjs), so the in-app connection check reports "STUN not reachable" on this box. The real PeerJS cloud + data-channel path is verified Node-to-Node with the actual src/net.js. No TURN server: strict NATs may fail (the help screen says so). Host leaving ends the room.
- Daily-challenge board is local only. HQ memory: 48 kHz stems decode to ~290 MB per track; High is meant for desktop / recent iPad & iPhone Pro; the first HQ download is large (cached afterwards). Switching to or from Performance reloads the page.
- Under software GL a race takes ~40-55 s wall to reach green (intro runs on game time); real devices should be much faster. Add-to-Home-Screen has no service worker, so there is no offline play.
